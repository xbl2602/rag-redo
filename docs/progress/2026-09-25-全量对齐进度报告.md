## 三、可能还没覆盖到（验证盲区，如实列出）

### 1. 检索质量评估的广度

- 旧评估集 12 题 + 自选 18 题都是**抽样**，不是穷尽证明；评估集黄金
  路径过时（库是活库），两边同样受影响但"打平"部分依赖过时判定。
- 只对比了 top-5 文件级；**块级排序、置信度数值逐位对比、翻页深度
  （top 20+）、folder 多值组合**没有系统性对比。
- 置信度只验证了档位分布，没有逐题数值对齐（fp16 vs fp32、切块边界
  差异都会引入低位扰动——旧项目自己也确认 fp16 扰动不影响档位）。

### 2. 断网导致的功能盲区

- **sidecar 清洗**：真实 sidecar 只有 MinerU 云端提取才产生；断网环境
  里这条路径只有单元测试覆盖，真库上从未真实生效过。
- **库简介 AI 生成**（需 LM Studio/LLM 服务）、**HyDE 查询增强**
  （默认关，需 LLM）——均未实测真实生成质量。
- 视觉/WEMM：同上，完全未实测。

### 3. 并发与生命周期场景

- **GUI/MCP/索引同时运行**时的 GPU 仲裁、模型抢占、空闲卸载时序——
  只在单元测试里验证过状态机，没有多进程真实并发实测。
- 长驻 MCP 进程跨多轮索引的 Token 标志复位、断点簿记清理——本轮
  刚移植，没有长期运行验证。
- 崩溃恢复：generation 原子性有测试，但真机 kill -9 级别的索引中途
  崩溃恢复没有实测（本轮确实 kill 过一次 CPU 索引，事后状态健康，
  但未做系统性验证）。

### 4. 等价性验证的方法论边界

- MCP 工具输出形状：旧项目是 text blob，rag-redo 是 dict 协议——
  这是登记过的架构决策；字段语义等价性做过逐工具审计，但**文案
  逐字对比**只覆盖了重点工具（advice 通道是经批准的偏离 BC-08）。
- note_relations/graph/dedup 在真库上的**新旧输出对比**没做
  （只验证了自身功能可用）。
- 导出→导入→检索等价性的**真库往返**验证没做（单元测试覆盖协议层）。
- "不存在其他偏离"在方法论上不可证明——每轮实测都曾抓出纸面审计
  漏掉的问题（本轮 3 个），持续检验是唯一手段。

### 5. 性能

- 只对齐了量级（索引 3.5 分钟、单查询 ~1.3 秒），没有做系统性基准
  （不同库规模、并发查询、冷/热缓存）。
