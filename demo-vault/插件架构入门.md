# 插件架构入门

## 为什么要插件化

一个软件如果所有功能都硬编码在一起，换一个 embedding 模型、加一种文件格式，都要改动核心代码。插件化架构把功能拆成一个个独立的模块，核心只负责发现、加载、启用/禁用这些模块，功能本身完全由插件实现。

## 两个核心组件

- **插件运行时**：负责扫描插件目录、校验清单、管理生命周期（加载/启用/禁用/卸载）、仲裁资源冲突。
- **数据流管理器**：负责定义数据怎么在插件之间流动，提供统一的存储读写入口。

## 单例扩展点和多值扩展点

有些扩展点同一时刻只能有一个生效实现（比如用哪个 embedding 模型），叫单例扩展点；有些扩展点可以同时存在多个（比如界面面板、MCP 工具），叫多值扩展点。核心不需要预先知道每一个可能出现的扩展点名字——是不是单例，由声明它的插件自己在清单里说明。

## 表格：扩展点类型举例

| 扩展点 | 类型 | 例子 |
|---|---|---|
| embedder | 单例 | BGE-M3 |
| vector_store | 单例 | Chroma |
| extractor:pdf | 多值 | 文字层提取器、OCR提取器 |
| gui_panel | 多值 | 库管理面板、搜索面板 |
